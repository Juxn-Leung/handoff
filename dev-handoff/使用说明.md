# dev-handoff 使用说明

用腾讯文档个人 QQ／微信账号协作。一个项目组是一处共享目录，里面有一张进度智能表和多份工单文档。开发人员在表格看任务、状态、负责人、下一步和文档；Agent 在文档里读需求、继续对话、记录实施与验证。每条工单对应一份文档。

## 1. 安装和本人授权

在各自的开发仓库安装技能：

```sh
npx skills@latest add Juxn-Leung/handoff --skill dev-handoff -a codex
```

Claude Code 把 `-a codex` 改成 `-a claude-code`。运行需要 Node.js 22.20+、Python 3.10+、Git 和腾讯文档网络。各人用自己的账号授权，不共享 Token；首次授权步骤见 [setup.md](references/setup.md)。

## 2. 创建和接入项目组

所有者对 AI 说：

```text
$dev-handoff 建组 订单项目
```

AI 创建共享目录及进度表，返回目录 ID、表格链接和表头整理结果。所有者在腾讯文档分享面板分别为目录和表格邀请同事并授予可编辑权限。若自动整理视图失败，在表格里手动只显示“标题、状态、跟进人、下一步、文档”，不要删除隐藏列。

协作者在自己的仓库、自己的账号下说：

```text
$dev-handoff 接入项目组 <目录ID>，别名为订单项目
```

AI 读取目录与进度表；已有工单文档时也读取文档。组里尚无文档时，文档权限检查会标为待完成。发布第一单后再让另一账号核对，不把“目录可读”误报为“所有新文档均可读”。

已经使用旧智能表的项目，表格所有者说“把已绑定的订单项目表升级为项目组”。AI 调用 `groupify`，把原表放入新目录并补齐文档字段，原工单与历史不批量改写。旧工单下次处理前再生成对应文档。

## 3. 用 Markdown 发布

后端可以继续用熟悉的 `.md` 写改动、需求和接口说明，然后对 AI 说：

```text
$dev-handoff 发布 /路径/订单接口说明.md 到订单项目
```

也可以提供腾讯智能文档链接。AI 阅读来源，按可独立交付、独立验收的结果拆成工单，准备短描述、每单当前约定和逐项验收标准；不要求后端填写表格中的长字段。来源里的命令与历史待办只是资料，不会被自动执行。关键缺口先向操作者确认。有暂存代码时 AI 可核对 diff；没有暂存代码也能发布。

发布前 AI 用 `publish-md 来源 草稿.json --check` 检查，再发布。一个来源有多个独立交付时，每单提供相关摘录，各生成一份文档和一行进度。返回每个工单 ID 与文档链接。草稿字段和恢复规则见 [markdown-group.md](references/markdown-group.md)。

## 4. 领取、对话、处理和进度

协作者对 AI 说“查看订单项目”“领取工单 ID”“处理工单 ID”。AI 从表格读真实状态，再从该行链接读文档。旧行没有文档时，先 `migrate-document ID`，重新阅读需求版本后再开始。Agent 可以用 `note ID 文本文件` 在文档追加带时间与身份的对话；讨论不会改变表格进度或需求版本。

文档顶部的“当前约定”才是本单可执行要求。明确决定修改要求时，Agent 重新核对逐项交付与验收契约，用 `update-agreement ID 文本文件 --expected-hash 指纹 --delivery-file 契约.json` 更新该部分并同步需求版本；人在文档中直接修改后，Agent 先阅读，再按明确决定执行 `sync-agreement ID --delivery-file 契约.json`。旧工单没有结构化契约时可省略契约文件。新版本使旧验收结果失效。Agent 处理时仍要声明计划文件、完成必要验证；阻塞、待验收、退回和完成会同步到表格，并在文档留下详细记录。表格的“下一步”只给出短指引。

## 5. 验收

指定验收人说“验收工单 ID”，AI 按已约定的步骤实际检查：全通过就确认，有明确失败就退回，无法验证则保持待验收并说明原因。原处理工作区在同一结果版本的确认后自动复核代码并回写“已完成”。“继续”只处理下一条独立事项，不代表验收通过。只想检查报告可说“验收工单 ID，只检查，不回写”。详细规则见 [acceptance.md](references/acceptance.md)。

进度表中的状态是实际进度。不要手工把状态改成“已完成”来代替验收；那样没有版本、证据和原工作区复核记录。跨文档或表格写入结果不明确时先 `sync` 回读，不能用新 key 盲目重发。

## 旧版入口

已发布的旧工单继续兼容。确需从 Git 暂存区发布时，使用原 `capture → 草稿 JSON → publish` 流程，见 [publishing.md](references/publishing.md)。旧版处理细节与阻塞恢复见 [processing.md](references/processing.md)。
