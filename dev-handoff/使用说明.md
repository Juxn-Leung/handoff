# 腾讯文档个人账号共享工单

协作者分别使用自己的个人 QQ／微信账号、自己的 Token 和自己的代码仓库，共享同一张腾讯智能表。日常在 AI 聊天中操作，不必手动运行脚本。

**AI 完成后停在“待验收”；“继续”只开始下一条，只有操作者明确通过指定结果才回写“已完成”。**

## 1. 安装

使用 npm / npx 从 Git 仓库安装，无需下载安装包：

```sh
# Codex，当前项目
npx skills@latest add Juxn-Leung/handoff --skill dev-handoff -a codex
# Claude Code，当前项目
npx skills@latest add Juxn-Leung/handoff --skill dev-handoff -a claude-code
```

加 `-g` 可安装为个人通用技能。安装需要 Node.js 22.20+；skills CLI 会安装完整的 scripts、references 和 agents。

已有安装在原项目运行 `npx skills@latest update dev-handoff -p`，全局安装改用 `-g`，然后让 AI 重新读取已安装的 SKILL.md。双账号联调也可以通过聊天说“对共享表 URL 的测试工单 ID 执行双账号联调第一轮，确认当前版本后退回”，由 AI 检查版本并执行；不必记住 `reviewer-first`，也不必另传联调包。详见 [联调入口](references/acceptance.md#更新已安装技能后继续联调)。

需要 Python 3.10+、Git 和能访问腾讯文档的网络。下面用 Codex `$dev-handoff` 举例，Claude Code 换成 `/dev-handoff`。

安装完成后按下一节建表或接入。需要授权时，AI 会生成本人的网页授权链接：用自己的微信或 QQ 登录，点击“确认授权”，显示“已授权”后回到聊天回复“已授权”，AI 就会继续原来的操作。Token 自动保存在本人电脑，不需要贴进聊天。

详细安装和授权排查见 [setup.md](references/setup.md)。

## 2. 一人建表，邀请指定同事

任意一人输入：

```text
$dev-handoff 建表 订单项目，不限定分工
```

也可以在建表时指定“分工选项为：前端、后端、测试”，或其他自定义名称。分工是成员说明，不限制领取；默认可自由填写或留空。

返回的腾讯智能表包含：

| 工作表 | 用途 |
|---|---|
| 工单 | 发布人、跟进人、状态、交接说明、验收标准、依赖和处理结果 |
| 跟进记录 | 领取、分配、开始、阻塞、退回、待验收、验收通过的历史事件 |
| 成员 | 每位协作者登记的稳定账号 ID、姓名和可选分工 |

建表会尝试整理默认工单视图，只显示日常业务字段；若平台拒绝，会明确报告表头待整理，不重复建表。目标是：账号 ID、版本、证据与恢复字段隐藏，AI 仍可读写。原始说明、来源、关联和验收信息可通过工单详情查看。

建表人在腾讯文档右上角“分享”面板添加同事使用的个人账号，设为“可编辑”，自己把链接发给同事。不必把表格改成所有人可编辑，也不要共享 Token。

另一位同事在自己的开发仓库只需输入：

```text
$dev-handoff 接入 <真实腾讯智能表URL>
```

首次接入时打开 AI 返回的授权链接，使用被邀请的账号确认授权，再回复“已授权”。AI 自动完成账号检查、绑定、成员登记和队列检查，最后展示接入结果。已授权时直接完成；不需要再逐步输入“绑定”“加入”“查看成员”。

新绑定的别名默认使用“开发对接”，已有绑定沿用原别名，也可在指令中指定“别名为订单项目”。分工默认留空；如果表格要求固定选项，AI 才询问。初建表的一方也加入；需要时可随时用“查看成员”核对。

**表格编辑权限决定能否读写，成员和跟进人 ID 决定由谁处理，两者分别设置。**

## 3. 后端发布，前端领取

以后端实现订单接口、前端接入页面为例。后端先在编辑器里暂存本次交接的代码，再输入：

```text
$dev-handoff 发布 订单项目
```

AI 读取暂存版本，按独立接入和验收的事项拆单，写清路径与方法、鉴权、请求参数、响应、错误处理、示例、联调可用性和验收标准。有关键缺口会先问，不自动暂存、提交、推送或部署。

每单明确影响应用、接手方交付、验证证据提供方和验收责任。能独立验收的应用分别成单，公共修改尽早明确归属；后端回归测试是变更来源时，不直接照抄为前端的全部验收标准。真实联调是否是本单必要条件，要在发布时约定，不能在做完后缩小范围。

新工单还要从共享成员中明确实际验收人，并把每项验收标准关联操作步骤、预期结果和检查项目。同名成员用稳定账号区分，不用分工代替身份。

AI 发布前检查应用和共享契约重叠，接手方再用自己仓库的计划文件预检。提示用于调整拆单或安排顺序，不自动建立依赖，也不放松待验收保护。

发布后工单状态是“待对接”，跟进人先留空。前端输入：

```text
$dev-handoff 查看 订单项目
$dev-handoff 查看 订单项目，只看 admin-app
$dev-handoff 领取 <工单ID>
```

AI 可以领取前置依赖已完成且没有其他跟进人的事项，不按前端、后端或其他分工限制。也可以由后端输入“把工单 X 分配给前端”，AI 从成员表解析唯一账号 ID 后分配。相同昵称要按 ID 消歧，不默认选第一位。

队列默认最多 20 条摘要，显示范围、标题、状态、阻塞原因和下一步，并报告总数与剩余条数。按应用筛选也会包含全局共享事项；范围未知的旧工单单独提醒，不猜测应用。需要完整需求时查看工单，验收时查看结果证据。

反向对接同样可用：前端发布待后端实现的接口需求，后端领取。发布说明要明确标注实现与可用状态。

## 4. 每次处理一条

领取后输入“处理工单 X”。AI 阅读完整说明和交付约定，核对当前仓库能否承接，提前预检计划文件，成功开始后再修改代码。也可输入“预检这一组事项”，提前找出公共字典等共享文件；预检本身不领取或开始。扩大范围前先检查，不能自动跨仓库修改。

完成代码与适当验证后，AI 写入“待验收”，展示结果、验证记录、结果版本、队列数量和下一条建议，随后停止。

这时回复“继续”可以处理下一条独立事项。它不会把前一条自动验收。前置工单尚未验收、文件重叠、公共契约影响尚未核清时，AI 会暂停或建议独立事项。

缺少接口契约或环境无法推进时写入“阻塞”，包含原因、已尝试方法和所需信息。解除后明确说明工单 ID 与解除条件，再恢复处理。

文件或工单依赖阻塞会关联具体文件或工单，查看时重新读取其当前状态和结果版本；历史保留当时原因。条件解除只提示可恢复，仍需明确恢复。必要验证缺失不能提交待验收，mock 不能代替声明为必要条件的真实联调；外部验收事项未完成时可以保留本单待验收，满足约定门槛后再验收。

## 5. 人工验收回写

新工单提交时逐项附上实际结果、可阅读证据和证据指纹。指定验收人使用自己的账号查看材料，按步骤核对预期和实际结果，明确通过已展示的版本后输入：

```text
$dev-handoff 验收通过 <工单ID>
```

AI 只允许指定验收人逐项确认，并把确认绑定同一结果版本。确认后仍为“待验收”；原处理人回到原工作区输入“回写已确认的验收 工单ID”，AI 核对需求、完整确认、原执行会话、代码指纹和依赖后回写“已完成”。实际验收人和确认时间写入工单，原处理人的回写动作另留日志。同一人、同一工作区同时承担两种角色时可以连续完成。

业务材料可以跨账号、跨工作区验收，最终代码复核与完成回写仍须回到原处理账号和工作区。跨工作区的材料查看会明确标记尚未检查原代码，不跳过指纹保护。旧工单没有指定验收人和逐项标准时，继续沿用原处理账号、原工作区的原有流程。

代码变化后重新验证，并再次等待指定验收人通过新版本。未满足要求时输入“退回 工单ID 原因”，AI 绑定已审阅版本及标准保存反馈，恢复到待对接；原处理人也可以撤回本人的待验收结果。重提始终产生新版本，旧确认不会自动复用。“通过并继续”只有在原工作区完成回写后才开始下一条。

不要直接在表格里把状态改成已完成来替代技能验收，那样不能生成受代码证据约束的验收记录。

## 6. 多账号、恢复和并发

每位协作者在各自工作区保留 `.dev-handoff-local/`，不要复制给对方。项目绑定 `.dev-handoff.json` 只含非敏感表信息，可以各自绑定相同 URL。

写入超时先让 AI 执行 sync 回读恢复，按工单键和事件键去重。不要清空检查点或改 key 重复发单。关闭聊天后在原账号、原工作区恢复处理中事项。

一个工作区同一时间只处理一条；可以保留多条互不影响的待验收结果。腾讯 API 没有跨机器的条件写原子锁，不要让两个会话同时领取或开发同一条工单。

第二台电脑首次接入后，按 [setup.md 的跨设备验收步骤](references/setup.md)验证实际访问、发布、领取与回写。两个模拟账号的自动化测试不能代替这一真实联调。

| 操作 | 日常输入 |
|---|---|
| 建表 | `$dev-handoff 建表 项目名` |
| 接入已有表 | `$dev-handoff 接入 URL`（自动授权引导、绑定、加入和检查） |
| 看成员 | `$dev-handoff 查看成员` |
| 发布 | `$dev-handoff 发布 别名` |
| 只读队列 | `$dev-handoff 查看 别名` |
| 按应用查看 | `$dev-handoff 查看 别名，只看 admin-app` |
| 提前预检 | `$dev-handoff 预检 工单ID`（AI 声明接手方文件） |
| 领取 | `$dev-handoff 领取 工单ID` |
| 处理 | `$dev-handoff 处理 工单ID` |
| 下一条 | `继续` |
| 验收 | `$dev-handoff 验收通过 工单ID` |
| 原工作区回写 | `$dev-handoff 回写已确认的验收 工单ID` |
| 退回 | `$dev-handoff 退回 工单ID 原因` |
